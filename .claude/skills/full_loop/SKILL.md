# full_loop — 選定〜実装〜検証〜/end を一括実行する

`/start`(候補提示のみ)と `/end`(締めのみ)を、ユーザーの一括実行指示のもとで最後まで繋げる。**着手タスクの選定をユーザー承認なしで進めてよい、というのがこのスキル固有の許可**。終了条件(`CLAUDE.md` §14.3)と確認ルール(§14.5)は通常どおり効く。**`main` への反映(= デプロイ)は常に都度確認**。

## サブエージェントへの委譲

親は選定・判断・ユーザー確認・commit/push のみを担い、実装は `implementer`、検証は `verifier`、設計・原因究明は `architect`、差分レビューは `adversary` に委譲する(`Agent` ツールに `model` は渡さない。各定義の `model:` が使われる)。

**委譲時の共通ルール**:
- 委譲先は `CLAUDE.md` の文脈を持たない。プロンプトに「報告は日本語で」と、確定済みの仕様(該当する `CLAUDE.md` の節番号と要点、§14.7 の補足)、変更対象、完了条件を書き出す。
- 仕様に確定値が無く、実装コードを読まないと決められない場合、親が `js/` を読んで決めてから委譲しない。「`js/app.js` の◯◯を読み、△△を確定したうえで実装してください」と調査・決定ごと渡す(設計判断が伴うなら `architect`)。
- `architect` を呼ぶ条件: 「⚠️上位モデルで実施」タスク/原因不明・再発バグ/`implementer` が 2 回失敗した時/データ項目名・画面構成など新規決定を伴う時。
- 非委譲のしきい値・同型 S タスクのバッチ委譲は `CLAUDE.md` §14.4 のとおり。

## 手順

1. **状況確認**: `start` スキルの手順 1〜4 と同じ(git 同期・`tools/verify.mjs`・引き継ぎ・未完了行の抽出)。NG なら報告して止まる。
   - `NEXT_SESSION.md` の直近節に「**検証待ち**」の記載があれば、手順 2・3 をスキップして手順 4 から再開する。
2. **タスク選定**: 「依存が満たされた最上位のタスク」を 1 つ選び、選定理由を一言共有して進む(承認は待たない)。
   - 依存充足済みの「⚠️上位モデルで実施」タスクがあれば優先し、`architect` に設計書+タスク分解を作らせる(コードは書かない)。
   - 「⚠️ユーザー実施」や「`full_loop` の自動選定対象外」のタスクは選ばない。選べるタスクが無ければ状況(ブロック理由・着手可能になる条件)を報告して `AskUserQuestion` で指示を仰ぎ、終了する。
   - 着手前に「実装+検証まで 1 ループに収まるか」を一言見積もる。収まらなければ実装フェーズと検証フェーズに分けるか、別の S タスクへ切り替えるかを選択式で確認する。
3. **実装**: `implementer` へ委譲する(仕様の節・変更対象・完了条件・「HTML/CSS/JS/vendor/icons を変えたら `sw.js` の `CACHE_VERSION` を上げる」を必ず書く)。
   - 実装が長引き、このセッションで検証まで終えるのが難しい場合は、`NEXT_SESSION.md` に「検証待ち」として実装内容・変更ファイル・次の検証手順を書き、commit(push はしない)してユーザーへ報告し終える。
4. **検証**: `/verify` スキルの手順で `verifier` へ委譲する。NG なら親が原因を判断し、方針が明らかなら `implementer`、原因不明・2 回目以降の失敗なら `architect` へ差し戻す(連続失敗の回数を数える)。
   - 変更ファイル数が 15 超、またはフェーズ完了の区切りでは、検証と並行して `adversary` に差分レビューを依頼する。Critical/Major の指摘は報告に留めず、その場で `implementer` に差し戻して直す。
5. **commit / push**: 検証が全項目パスなら作業ブランチへ commit/push する(確認不要)。`main` への反映が必要なタスクは、内容を説明して `AskUserQuestion` で許可を得てから行う。
6. **`/end` の手順をそのまま実行する**(`NEXT_SESSION.md` → マスタープラン → 教訓 → commit/push → 継続 vs `/clear` の提案)。

## 注意

- 終了条件(連続 3 回失敗・ターン 30)に達したら、実装途中でも直ちに手順 6 に切り替えて停止する。
- 削除を伴う操作・`--force` 系 push・`main` への反映は都度確認。分類器にブロックされたら委譲で回避せず、説明して許可を得る。
